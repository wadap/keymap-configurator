# 決定事項

- ユーザーが提案済みの自動デプロイを承認し、develop/main運用を追加指定したため、この範囲を実装する。
- 長期鍵のGitHub Secret登録ではなくOIDCを使用する。ビルド中にはデプロイ用認証を渡さない。
- mainのワークフローは並行デプロイを避け、古いSHAの再実行は公開をスキップする。
- 初回設定もdevelopからmainへのPRを使用して動作確認する。
- 既存のローカル履歴保管ブランチはpushしない。
- 独立レビューで、古い実行の再実行が最新mainの待機実行を取り消す競合を検出。mainの検証を実行IDごとに分離し、公開ジョブは`queue: max`で順番に処理する。最新mainとのSHA照合も維持する。
